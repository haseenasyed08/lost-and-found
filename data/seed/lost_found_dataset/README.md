# Synthetic Lost & Found Dataset

Fully synthetic (fictional campus, users, items). Generated by `gen_dataset.py` (seed 42, 700 base items).
Re-run with a different `--seed` or `--items` to make more data.

## Files
| File | Rows | What it is |
|---|---|---|
| `lost_reports.csv` | 772 | Owner-written lost reports (noisy, sometimes vague, 8% Hinglish, 10% typos) |
| `found_reports.csv` | 770 | Finder-written found reports, with private `hidden_details_json` (3 details the finder saw) |
| `matches_ground_truth.csv` | 662 | True (lost_id, found_id) pairs |
| `items_ground_truth.csv` | 880 | The real objects behind the reports: true attributes, hidden details, twin group, fate |
| `candidate_pairs.csv` | 4,269 | Labeled (lost, found) pairs for training/evaluating a ranker, with hard negatives |
| `verification_claims.csv` | 1,052 | Ownership claims: 3 private questions, answers, per-answer correctness, decision label |
| `campus_places.csv` | 16 | Fictional campus places with x/y metres and lat/lon |

## Key design choices
- **Split** (`train/val/test`, 70/15/15) is by item group, so an item and its look-alike twin never straddle splits. Build candidate pools *within* a split to avoid leakage.
- **Twins** (20% of items): same category, brand and colour, different details and often the same place and day. These are the `twin_hard_negative` pairs.
- **Noise**: owner may report a neighbouring place (25%), colour/category paraphrases, brand omitted or misremembered, found at Security Desk (8%), found time after lost time (median about 4 h, up to about 4 days).
- **Pair labels**: `positive`, `twin_hard_negative`, `same_group_nearby`, `random`. `lost_has_true_match=False` rows test "no match exists" behaviour.
- **Verification label rule**: 3 of 3 correct = `approve`, 2 of 3 = `manual_review`, 0 or 1 = `reject`. Claim types: `genuine_full`, `genuine_partial`, `impostor`.

## Reference baselines (test split, ranking over all found reports in the split)
- TF-IDF on descriptions only: Recall@1 0.34, Recall@5 0.66
- TF-IDF plus a distance/time prior: Recall@1 0.56, Recall@5 0.86

Your multimodal model, a learned ranker and fine-grained attribute matching should beat these.

## Important limitations
- **No real images.** `image_file` is empty. `image_caption` is a synthetic stand-in for what a captioner would say about a photo. To get real images, attach photos of everyday items (your own, or from Amazon Berkeley Objects) to each `item_id`, using two different photos per item for the lost and found sides.
- Text is template-generated, so it is cleaner and less varied than real reports. Say so in your report, and validate on a small real sample.
- Locations are a made-up campus layout. Replace `campus_places.csv` with your own campus coordinates if you like.
